Chapter 1

The core ideas

Five words and one rule are all you need to read the rest of this guide.

The five words

WordMeaningExample
ProfileOne app's list of what it needs to run.The request logger's profile, request-logger-http
ConditionOne thing the app needs, such as an API or a cache.todos-api, request-cache
ExtensionDefines the words a profile can use, and checks them.Common Integrations, Env Configuration, AWS Object Store
ProfilerReads your code and writes the profile.The Go, Java, Python, and TypeScript profilers, run by rc-cli
AdapterTurns a profile into requests for one platform.The Kratix ApplicationRelease Promise in the demo

Who does what

Five roles, and what each one does. They match the conformance classes of the specification.

RoleWhat they doExample
Extension authorDefines the words a profile can useCommon Integrations
DeveloperDeclares what the app needsA few lines in the app's own code
ProfilerReads the code and writes the profilerc profile generate
ValidatorChecks a profile against the core and its extensionsrc profile validate
Platform teamDecides how to provide each need, through an adapterThe Kratix Promises in the demo

Demand and fulfillment

A profile is demand: what the app needs. Fulfillment is the platform's job: how to provide it. Tools like Radius, Crossplane, and Kratix start from a need that is already known, and a profile is where that need is written down.

Developer→Runtime Conditions Profile→Radius, Crossplane, Kratix…

The profile (demand)The platform (fulfillment)
SaysWhat the app needsHow to provide it
Example"A Redis cache, read through REDIS_URL"A Redis Promise in Kratix, or a managed Redis in the cloud
Written byThe developerThe platform team
Changes whenThe app needs something newThe platform changes how it provides things

An adapter connects the two for one platform. Chapter 6 follows one through the demo.
